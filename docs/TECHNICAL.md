## 1. RAG 问答流程

### 1.1 完整问答链路

```
用户提问
    │
    ▼
┌─────────────────┐
│  1. 意图识别     │ ← 判断问题类型（事实/流程/政策/闲聊）
└────────────────┘
         │
         ▼
┌─────────────────┐
│  2. 语义缓存检查  │ ← 相似度 > 0.82 直接返回缓存答案
└────────┬────────┘
         │ (未命中)
         ▼
┌─────────────────┐
│  3. 查询扩展     │ ← 同义词扩展，生成多个变体问题
└────────┬────────
         │
         ▼
┌─────────────────┐
│  4. 多路召回     │ ← 三路检索 + RRF 融合
│  ├─ 路径1       │   原始问题向量检索
│  ├─ 路径2       │   扩展问题向量检索
│  └─ 路径3       │   BM25 关键词检索
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  5. 拆分组扩展   │ ← 补充同源拆分子文档的候选 chunk
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  6. 混合检索     │ ← 向量 + BM25 + 动态权重融合
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  7. 重排序       │ ← DashScope Reranker API / 启发式降级
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  8. 质量过滤     │ ← 自适应阈值（0.30/0.15）+ 去重
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  9. 权限过滤     │ ← 根据用户角色过滤文档
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  10. 跨文档合并  │ ← 同源子文档 chunk 合并为完整上下文
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  11. 提示词构建  │ ← 组装上下文 + 对话历史 + 系统提示
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  12. LLM 调用   │ ← 通义千问生成回答（指数退避重试）
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  13. 答案验证    │ ← 多级置信度评估（AI + 规则）
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  14. 缓存结果    │ ← 存入语义缓存供后续使用
└────────┬────────┘
         │
         ▼
      返回回答
```

### 1.2 意图识别

**实现文件**：`backend/app/services/intent_classifier.py`

基于规则和关键词的轻量级分类器，无需额外 AI 模型：

| 意图类型 | 识别关键词 | 处理策略 |
|---------|-----------|---------|
| **事实型** | 什么时候、在哪里、是谁、多少、电话 | 精确向量检索，快速定位 |
| **流程型** | 怎么、如何、办理流程、步骤、怎么办 | 扩展检索 + 多路召回 |
| **政策型** | 规定、要求、条件、能不能、限制 | 多路召回 + 重排序 |
| **闲聊型** | 你好、谢谢、再见、哈哈 | 直接回复，跳过检索 |

### 1.3 多路召回（Multi-Path Retrieval）

**实现文件**：`backend/app/services/multi_path_retrieval.py`

使用三种检索路径提高召回率，通过 RRF（Reciprocal Rank Fusion）算法融合：

```python
# 扩大检索范围，确保跨子文档覆盖
expanded_top_k = max(top_k, 15)

# 路径1：原始问题向量检索
embedding = embedder.embed(question, db=db)
results1 = vector_store.search(query_embedding=embedding, top_k=expanded_top_k)

# 路径2：扩展问题向量检索（同义词扩展）
expanded_query = QueryExpansionService.expand_query_for_retrieval(question)  # "怎么办理休学" → "怎么办理休学 如何办理休学 休学申请流程"
embedding2 = embedder.embed(expanded_query, db=db)
results2 = vector_store.search(query_embedding=embedding2, top_k=expanded_top_k)

# 路径3：BM25 关键词检索
results3 = bm25_service.search(question, top_k=expanded_top_k)

# RRF 融合：score(d) = Σ 1/(k + rank_i(d))，k=60
fused = rrf_fusion([results1, results2, results3], top_k=expanded_top_k)

# 跨文档多样性增强：确保每个拆分组至少返回 1-2 个 chunk
diversified = ensure_doc_diversity(fused, min_per_doc=2)
```

### 1.4 重排序（Reranking）

**实现文件**：`backend/app/services/reranker_service.py`

采用**DashScope Reranker API 优先 + 启发式降级**的双模式策略：

```python
# 优先使用 DashScope Reranker API（如 gte-rerank）
response = dashscope.TextReRank.call(
    model=model_name,
    query=query,
    documents=documents,
    top_n=len(documents)
)

# API 不可用时自动降级到启发式重排序
combined_score = 0.7 * vector_score + 0.3 * keyword_overlap
```

这种方式在保证重排序精度的同时，通过降级机制确保服务高可用。

### 1.5 答案验证

**实现文件**：`backend/app/services/answer_verifier.py`

对 LLM 生成的答案进行多级置信度评估：

1. **空答案检测**
2. **不确定表述检测**：检测"我不确定"、"据说"、"据我所知"、"无法确认"、"我不清楚"、"不太确定"、"我无法"等不确定表述
3. **上下文覆盖率**：计算答案中有多少内容来自检索上下文（最低要求 30%）
4. **AI 验证**：调用 LLM 判断答案是否基于上下文，返回多级置信度（0.2~0.9）

**判断标准**：
- 采用多级置信度评估，而非二元"是/否"判断
- 只有当 AI 置信度 **且** 规则置信度都低于 0.4 时才标记为无效
- AI 验证解析失败时默认答案无效，确保系统准确性优先
- 无 AI 验证时，规则判断阈值为 0.35，避免过度拦截正常答案

## 2. 核心服务模块

### 2.1 检索服务（RetrievalService）

**实现文件**：`backend/app/services/retrieval_service.py`

整合所有检索优化技术的核心服务：

```python
class RetrievalService:
    def retrieve(self, question, top_k=5, db=None, user=None):
        # 1. 语义缓存检查
        # 2. 意图识别
        # 3. 查询扩展
        # 4. 多路召回
        # 5. 拆分组扩展（补充同源拆分子文档的候选 chunk）
        # 6. 混合检索（向量 + BM25 + 动态权重融合）
        # 7. 重排序
        # 8. 质量过滤
        # 9. 权限过滤
        # 10. 缓存结果
```

**拆分组扩展**：当检索结果命中拆分文档时，补充同源其他文档的上下文，确保大文件拆分后的内容完整性。

**混合检索**：
- 惰性构建全量 BM25 索引：首次检索时从向量库查询所有子块内容并构建，后续复用
- 动态权重：根据意图类型调整向量/BM25 权重比例
  - 事实型：向量 0.7 + BM25 0.3
  - 流程型：向量 0.4 + BM25 0.6
  - 政策型：向量 0.5 + BM25 0.5
  - 闲聊型：向量 0.8 + BM25 0.2
- 按 `parent_id` 聚合分数，与向量检索结果正确对齐

### 2.2 向量化服务（EmbeddingService）

**实现文件**：`backend/app/services/embedding_service.py`

- 调用通义千问 Embedding API
- Redis 缓存（7 天 TTL），相同文本不重复调用
- 指数退避重试机制（最多 3 次）
- 批量处理优化（batch_size=10）
- 动态模型选择（从数据库读取激活配置）

### 2.3 语义缓存（SemanticCache）

**实现文件**：`backend/app/services/semantic_cache.py`

- 将问题向量化后存入 Redis
- 新问题时计算余弦相似度
- 相似度 > 0.82 直接返回缓存答案
- 最大缓存 1000 条
- **效果**：相似问题响应时间从 ~3s 降至 ~50ms

### 2.4 查询扩展（QueryExpansion）

**实现文件**：`backend/app/services/query_expansion.py`

- 内置教育领域同义词库
- **追加同义词**：将原始问题中的关键词替换为同义词，追加到查询列表（非替换原始查询）
- 示例：`"怎么办理休学"` → `["怎么办理休学", "如何办理休学", "休学申请流程", "休学怎么办"]`
- **AI 扩展模式**：调用 LLM 生成语义相似的变体问题，失败时降级到规则扩展

### 2.5 BM25 关键词检索

**实现文件**：`backend/app/services/bm25_service.py`

- 基于 BM25 算法的关键词检索
- **惰性构建全量索引**：首次检索时从向量库查询所有子块内容并构建索引，后续复用（非系统启动时构建）
- 检索时记录 `doc_id → parent_id` 映射，实现按文档唯一标识对齐
- 混合检索时按 `parent_id` 聚合分数（同一父块的多个子块取最高分），与向量检索结果正确对齐
- 与向量检索互补：向量擅长语义匹配，BM25 擅长精确关键词匹配

### 2.6 质量过滤器（RetrievalQualityFilter）

**实现文件**：`backend/app/services/retrieval_quality.py`

- **自适应阈值策略**：
  - 第一遍：高阈值（0.30）过滤
  - 结果充足（≥3 条）直接返回
  - 结果不足：降级到低阈值（0.15）
- **Reranker 评分优先**：当重排序环节产生 `rerank_score` 时，优先使用 reranker 评分代替原始混合评分进行过滤，确保重排序结果被正确采纳
- **去重**：基于 Jaccard 相似度（阈值 0.9）
- **内容长度过滤**：最低 20 字符

### 2.7 权限过滤器（PermissionFilter）

**实现文件**：`backend/app/services/permission_filter.py`

- 根据用户角色过滤文档
- 学生只能访问公开文档
- 教师可访问公开 + 内部文档
- 管理员可访问全部文档

### 2.8 对话摘要服务（SummaryService）

**实现文件**：`backend/app/services/summary_service.py`

- **AI 模式**：调用 LLM 将对话历史压缩为语义摘要，保留关键上下文
- **截断模式（Fallback）**：基于 Token 估算自动截断，保留最近的消息
- 两种模式结合，优先使用 AI 摘要，失败时自动降级
- 超阈值（1500 tokens）时触发压缩

### 2.9 问答服务（QAService）

**实现文件**：`backend/app/services/qa_service.py`

整合检索、提示词构建、LLM 调用的完整问答流程：

- **跨子文档上下文合并**：检测检索结果中来自同一原文档的多个子文档 chunk，将它们的 parent_content 合并，确保 LLM 看到完整的跨部分上下文
- **智能对话历史管理**：根据 Token 预算自动决定是否压缩历史
  - 摘要关闭时：截断保留最近 4 条消息（2 轮对话）
  - 摘要启用时：AI 压缩历史 + 保留最近 2 条消息（1 轮对话）
- **多级置信度评估**：基于检索分数计算答案置信度（高/中/低）
- **答案验证**：可选启用 AI 验证 + 规则验证，确保答案质量
- **流式输出**：支持 SSE 流式返回，实时展示生成过程

**跨子文档上下文合并流程**：
```python
# 1. 按 split_group_id 分组检索结果（若无 split_group_id 则按 document_id）
# 2. 若只有 1 个分组，直接返回（无需合并）
# 3. 对每个分组，合并来自不同 parent_id 的 chunk 的 parent_content（用 "\n\n---\n\n" 连接）
# 4. 设置 child_content 为合并内容的前 500 字符
# 5. 标记 _merged=True 和 _source_count=分组内 chunk 数量
# 6. 按 score 重新排序，确保相关性最高的内容优先
```

## 3. 文档处理流程

### 3.1 完整处理链路

```
上传文件
    │
    ▼
┌─────────────────┐
│  格式校验        │ ← PDF/DOC/DOCX/TXT/MD（禁止 Excel/CSV）
└────────────────┘
         │
         ▼
┌─────────────────┐
│  临时存储        │ ← uploads/temp_documents/
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  预处理          │ ← 自动剔除封面/目录/版权/参考文献/页眉页脚
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  文本提取        │ ← 可编辑 PDF: pdfplumber+PyMuPDF
│                  │    扫描 PDF: PaddleOCR+PP-StructureV2 版面分析
│                  │    DOCX/DOC: python-docx
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  清洗 (三级)     │ ← 粗洗→精洗+校验→轻校验
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  文本分块        │ ← 父子块机制（父块1500字/子块500字）
│                  │    大文件自动拆分为多子文档并行处理
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  向量化          │ ← 通义千问 Embedding（批量 + 缓存）
└────────┬────────┘
         │
         ▼
┌─────────────────
│  存入 Milvus     │ ← 向量 + 元数据（父子块机制）
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  更新 BM25 索引  │ ← 关键词索引
└────────────────┘
         │
         ▼
      处理完成
```

**预处理**（`document_preprocessor.py`）：在上传后、解析前自动识别并剔除无效页面：
- 封面/扉页（检测封面关键词 + 低内容密度）
- 目录页（检测目录标题 + 高标点密度）
- 版权声明页（检测版权关键词）
- 参考文献/附录页
- 纯空白页
- 页眉页脚、页码、水印

**智能解析**（`document_parser.py`）：
- 自动检测 PDF 类型（可编辑/扫描/混合）
- 可编辑 PDF：主选 `pdfplumber`，备选 `PyMuPDF (fitz)`
- 扫描版 PDF：调用 `PaddleOCR + PP-StructureV2` 版面分析进行 OCR
- 混合页面：正文用原生提取 + 图片区域单独 OCR
- 低质量页面（识别率 < 60%）直接拦截
- 支持大文件拆分（> 50MB 自动拆分为多子文档并行处理）

**三级清洗**（`document_cleaner.py`）：
1. **全文粗洗**：特殊空白字符清理、控制字符移除、冗余空白合并、装饰线移除
2. **父块精洗+校验**：页码/页眉页脚剔除、模板化文案清理、汉字间空格修复、异常断行合并、低质量/高度重复内容拦截
3. **子块轻校验**：非空 + 最小长度校验

### 3.2 文本分块策略

**实现文件**：`backend/app/services/text_splitter.py`

采用**父子块机制**，兼顾检索精度和上下文完整性：

| 层级 | 大小 | 重叠 | 用途 |
|------|------|------|------|
| **父块** | 最大 1500 字符 | 200 字符 | 返回给 LLM 作为上下文 |
| **子块** | 最大 500 字符 | 60 字符 | 向量检索的最小单元 |

**三级分块策略**（按优先级）：
1. **章节级分块**：优先按章节标题（"第一章"、"一、"等）拆父块，每个章节内按条款编号（"第X条"、"1."等）拆子块
2. **条款级分块**：无章节标题时，按条款编号聚合为父块，每个条款作为子块
3. **回退分块**：完全无结构时，使用 `RecursiveCharacterTextSplitter` 按段落/句子切分

- **父子块机制**：子块用于精确检索（细粒度），父块包含子块及其上下文（完整语义），搜索结果返回父块内容作为 LLM 上下文

### 3.3 文档审核流程

| 角色 | 上传行为 | 审核要求 |
|------|---------|---------|
| **管理员** | 直接入库 | 无需审核 |
| **教师** | 待审核状态 | 需管理员审核通过后才入库 |
| **学生** | 不可上传 | - |

## 4. 用户与权限系统

### 4.1 三级权限体系

| 角色 | 权限 | 默认限制 |
|------|------|---------|
| **学生** | 提问、查看历史、查看公告 | 每日提问 100 次 |
| **教师** | 学生权限 + 上传文档 | 每日上传 10 次 |
| **管理员** | 全部权限 + 用户管理、文档审核、系统设置 | 无限制 |

### 4.2 用户管理功能

- **用户列表**：分页查看所有用户
- **限制管理**：设置用户每日提问/上传次数上限
- **封禁/解封**：临时封禁违规用户（支持设置截止时间）
- **教师审核**：审核教师注册申请（通过/驳回）
- **每日计数重置**：跨天自动重置提问/上传计数

### 4.3 认证机制

- **JWT Token**：基于 python-jose 的 JWT 认证
- **密码加密**：bcrypt 哈希存储
- **会话管理**：记录登录 IP、时间、会话 ID
- **多设备登录**：支持多设备同时在线

## 5. 缓存策略

### 5.1 三级缓存体系

| 缓存类型 | 存储位置 | TTL | 用途 |
|---------|---------|-----|------|
| **检索缓存** | Redis | 1 小时 | 相同问题的检索结果 |
| **回答缓存** | Redis | 24 小时 | 相同问题的 LLM 回答 |
| **语义缓存** | Redis | 7 天 | 相似问题的向量 + 答案 |
| **向量化缓存** | Redis | 7 天 | 相同文本的向量结果 |

### 5.2 缓存键设计

```
embedding:{model_name}:{md5(text)}     # 向量化缓存
search:{md5(question)}                  # 检索缓存
answer:{md5(question)}                  # 回答缓存
semantic_cache:{md5(question)}          # 语义缓存
```

## 10. 检索质量评测体系

### 10.1 概述

项目建立了一套完整的检索质量评测体系，基于**金标准数据集（Golden Dataset）** 对 RAG 系统的检索环节进行定量评估，确保文档入库后检索质量可控、可衡量。

**评测文件位置**：`backend/tests/evaluation/`

| 文件 | 说明 |
|------|------|
| `golden_dataset.py` | 金标准数据集，包含 29 个标注问答对 |
| `retrieval_evaluator.py` | 评测引擎，执行检索并计算指标 |
| `conftest.py` | Pytest fixture，提供 mock/real 评测器实例 |
| `test_retrieval_evaluation.py` | 评测测试用例 |

### 10.2 金标准数据集

基于**上海交通大学本科生学生手册（2025版）** 构建，29 个 QA 对覆盖以下类别：

| 类别 | 题数 | 示例问题 |
|------|------|---------|
| 校训与基本规定 | 3 | 交大校训是什么？学生享有哪些权利？ |
| 学籍管理 | 5 | 新生如何注册？能否转专业？ |
| 成绩与考核 | 3 | 体育课如何评定？考试作弊会怎样？ |
| 休学与复学 | 2 | 如何申请休学？应征入伍能保留学籍吗？ |
| 退学警告与试读 | 2 | 退学警告和试读制度是怎样的？ |
| 毕业与学位 | 2 | 最长学习年限？结业和肄业有什么区别？ |
| 学分与课程 | 2 | 免修条件？缓考怎么申请？ |
| 课堂纪律 | 2 | 考试纪律要求？作弊处分等级？ |
| 奖学金与资助 | 1 | 奖学金评选原则？ |
| 出国交流 | 2 | 公派出国要求？自费出国学籍处理？ |
| 校园生活 | 3 | 校园卡丢失？借用教室？宗教活动？ |
| 双学位与辅修 | 2 | 辅修学分要求？双学位证书标注？ |

每个 QA 对包含：`question`（问题）、`expected_keywords`（预期关键词列表）、`expected_content`（预期内容片段）、`source_section`（来源章节）、`difficulty`（easy/medium/hard）。

### 10.3 评测指标

评测器对每个 QA 对执行实际检索（top_k=5），将返回的 chunks 与预期关键词/内容做大小写不敏感匹配：

| 指标 | 计算方式 | 含义 |
|------|---------|------|
| **关键词召回率** | 命中的预期关键词数 / 预期关键词总数 | 检索结果覆盖预期的程度 |
| **Top-K 精准率** | 含关键词的 chunk 数 / 返回 chunk 总数 | 检索结果的精确程度 |
| **MRR@k** | 首个相关结果的倒数排名 | 排序质量（越接近 1 越好） |
| **通过率** | 至少命中 1 条预期关键词的 QA 占比 | 最低可用性门槛 |

### 10.4 运行模式

**Mock 模式**（离线，CI 友好）：
```bash
pytest tests/evaluation/ -m mock -v --no-cov
```
- 不依赖 Milvus、Embedding API 等外部服务
- 模拟检索始终返回包含所有预期关键词的结果
- 用于验证评测框架本身的逻辑正确性

**Real 模式**（需外部服务）：
```bash
pytest tests/evaluation/ -m real -v -s --no-cov
```
- 连接真实 Milvus + Embedding API（需文档已上传入库）
- 优先通过本地后端 API（`/api/v1/chat/eval-retrieve`）检索
- API 不可用时回退到直接调用 `RetrievalService`
- 输出详细评测报告
